# Tracing OpenCode

[MLflow Tracing](/genai/tracing) provides automatic tracing for [OpenCode](https://opencode.ai), a terminal-based agentic coding tool that supports multiple LLM providers including Claude, OpenAI, Google, and local models.

<ImageBox src="/images/llms/opencode/opencode-tracing.png" alt="OpenCode Tracing" />

After setting up the MLflow plugin, MLflow will automatically capture traces of your OpenCode conversations and log them to the specified MLflow experiment. The trace automatically captures information such as:

- User prompts and assistant responses
- Tool usage (file operations, bash commands, code edits, etc.)
- Conversation timing and duration per turn
- Token usage (input, output, cache, and total tokens)
- Cost of each LLM call

## Setup

OpenCode tracing is configured using the `@mlflow/opencode` plugin and plugin options or environment variables.

### Requirements

- [OpenCode CLI](https://opencode.ai) V2 installed
- The `@mlflow/opencode` npm package, version 1.x
- An MLflow tracking server running

:::note OpenCode V1
`@mlflow/opencode` 1.x supports only OpenCode V2. For OpenCode V1, pin `@mlflow/opencode@0.4` in the `plugin` list of your `opencode.json` and use the environment variables below. When 1.x is loaded on OpenCode V1, it does not trace and prints a message that tells you to pin `0.4`.
:::

### Step 1: Install the Plugin

```bash
opencode plugin add @mlflow/opencode
```

### Step 2: Configure OpenCode

Configure the plugin with the MLflow connection settings in your `opencode.json` file:

```json
{
  "plugins": [
    {
      "package": "@mlflow/opencode",
      "options": {
        "trackingUri": "http://localhost:5000",
        "experimentId": "123456"
      }
    }
  ]
}
```

### Step 3: Set Environment Variables (Optional)

Instead of plugin options, you can set environment variables. Set credentials, such as `MLFLOW_TRACKING_USERNAME` and `MLFLOW_TRACKING_PASSWORD`, only as environment variables:

```bash
export MLFLOW_TRACKING_URI=http://localhost:5000
export MLFLOW_EXPERIMENT_ID=123456
```

The OpenCode server process must have these variables. If the OpenCode background service is already running, restart it from a shell that has them:

```bash
opencode service restart
```

### Step 4: Start MLflow Server (if not already running)

You can start an MLflow server using [Docker Compose](/self-hosting/#docker-compose), which doesn't require a Python environment:

```bash
docker compose up -d
```

Alternatively, if you have Python and `mlflow` installed:

```bash
mlflow server
```

### Step 5: Run OpenCode

```bash
# Run OpenCode normally - tracing happens automatically
opencode
```

A trace is created when each session run ends, also when the run fails or is interrupted. Failed runs have an error status.

## Configuration Reference

The plugin is configured via plugin options or environment variables. Plugin options take precedence:

| Plugin Option  | Environment Variable    | Required | Description                                                |
| -------------- | ----------------------- | -------- | ---------------------------------------------------------- |
| `trackingUri`  | `MLFLOW_TRACKING_URI`   | Yes      | MLflow tracking server URI (e.g., `http://localhost:5000`) |
| `experimentId` | `MLFLOW_EXPERIMENT_ID`  | Yes      | Experiment ID to log traces to                             |
| `debug`        | `MLFLOW_OPENCODE_DEBUG` | No       | Set to `true` to enable debug logging to stderr            |

### Configuration Examples

```bash
# Local MLflow server
export MLFLOW_TRACKING_URI=http://localhost:5000
export MLFLOW_EXPERIMENT_ID=0

# Remote MLflow server
export MLFLOW_TRACKING_URI=http://mlflow.example.com:5000
export MLFLOW_EXPERIMENT_ID=123456

# Databricks MLflow
export MLFLOW_TRACKING_URI=databricks
export MLFLOW_EXPERIMENT_ID=123456789
```

## Token Usage

MLflow automatically tracks the token usage for each LLM call within OpenCode conversations. The token usage for each LLM call is logged in the `mlflow.chat.tokenUsage` attribute, including cache read and cache write tokens. The cost that OpenCode reports for each LLM call is logged in the `mlflow.llm.cost` attribute, split into input and output cost with the model's prices. The token usage and cost will be displayed in the Overview dashboard and the trace detail page.

<ImageBox src="/images/llms/opencode/opencode-overview.png" alt="OpenCode Trace Overview" />

## Session and User Tracking

The plugin automatically tracks session and user metadata for each trace:

- **Session ID**: Each OpenCode session is tagged with `mlflow.trace.session`, allowing you to group and filter traces by session.
- **User**: The current system user is tagged with `mlflow.trace.user`, making it easy to identify who initiated each conversation.

<ImageBox src="/images/llms/opencode/opencode-session.png" alt="OpenCode Session Tracking" />

You can use these metadata fields to filter traces in the MLflow UI or via the search API. For more details on session and user tracking, see [Track Users and Sessions](/genai/tracing/track-users-sessions).

## Troubleshooting

### Debug Logging

Enable debug logging to see detailed information about trace creation. Set the `debug` plugin option to `true`, or set the environment variable:

```bash
export MLFLOW_OPENCODE_DEBUG=true
opencode
```

Debug output is written to stderr to avoid interfering with OpenCode's TUI.

### Common Issues

**Traces not appearing:**

1. Verify the plugin options or environment variables are set correctly:

   ```bash
   echo $MLFLOW_TRACKING_URI
   echo $MLFLOW_EXPERIMENT_ID
   ```

2. Check that the MLflow server is accessible:

   ```bash
   curl $MLFLOW_TRACKING_URI/api/2.0/mlflow/experiments/list
   ```

3. Enable debug logging to see any errors:
   ```bash
   export MLFLOW_OPENCODE_DEBUG=true
   ```

**Plugin not loading:**

1. Verify that OpenCode loads the plugin with the ID `mlflow.tracing`:

   ```bash
   opencode plugin list
   ```

2. Check that `opencode.json` contains the plugin in the `plugins` list.

3. On OpenCode V1, pin `@mlflow/opencode@0.4`. Version 1.x requires OpenCode V2.

**Missing token usage:**

Token usage is only available when the LLM provider reports it. Some providers or configurations may not include token counts in their responses.

### Disable Tracing

To stop automatic tracing, remove the plugin from your `opencode.json`:

```json
{
  "plugins": []
}
```

Or unset the environment variables:

```bash
unset MLFLOW_TRACKING_URI
unset MLFLOW_EXPERIMENT_ID
```

Existing traces are preserved - disabling only stops new traces from being created.
