# Measuring Consistency with Repeated Runs

LLM applications are not deterministic, so a test case that passes in one <APILink fn="mlflow.genai.evaluate" /> run can fail in the next. To find such cases, run the same evaluation several times as nested runs and group the rows by test case.

## Run the evaluation several times

`evaluate` logs to the active run, so each repeat inside a nested run gets its own child run.

```python
import mlflow
import pandas as pd
from mlflow.genai.scorers import scorer


@scorer
def correct(outputs, expectations) -> bool:
    return outputs == expectations["expected_response"]


data = [
    {
        "inputs": {"question": "Is MLflow open source?"},
        "expectations": {"expected_response": "yes"},
    },
    # ...
]

frames = []
with mlflow.start_run(run_name="consistency"):
    for i in range(5):
        with mlflow.start_run(run_name=f"repeat-{i}", nested=True):
            result = mlflow.genai.evaluate(data=data, predict_fn=my_agent, scorers=[correct])
        frames.append(result.result_df.assign(repeat=i))

results = pd.concat(frames, ignore_index=True)
```

## Group the rows by test case

Each prediction gets a new trace ID, so group on the `request` column, which holds the inputs of the row:

```python
import json

# `request` holds dicts, which pandas cannot group on, so key on their JSON form.
results["case"] = results["request"].map(lambda r: json.dumps(r, sort_keys=True, default=str))

# Rows of one repeat with the same inputs cannot be told apart, so leave them out.
results = results[~results.duplicated(["repeat", "case"], keep=False)]

# A scorer error is neither a pass nor a fail, so skip it.
scored = results[results["correct/value"].notna()]
passed = scored["correct/value"].isin([True, "yes"])

per_case = passed.groupby(scored["case"]).agg(n="size", c="sum")
per_case["flaky"] = (per_case["c"] > 0) & (per_case["c"] < per_case["n"])
```

`n` is the number of repeats that scored the case and `c` is the number that passed. Do not match rows by position instead: a row whose trace cannot be read back is left out of `result_df`.

## Compute pass^k

pass^k, from [τ-bench](https://arxiv.org/abs/2406.12045), is the chance that k attempts at a test case all pass, averaged across test cases. For one case, C(c, k) / C(n, k) estimates it:

```python
import math

k = 3
per_case["pass^k"] = [
    math.comb(c, k) / math.comb(n, k) if n >= k else float("nan")
    for n, c in zip(per_case["n"], per_case["c"])
]
print(per_case["pass^k"].mean())
```

pass^1 is the mean pass rate per case. The further pass^k falls below it, the more your results depend on luck.

When an LLM judge scores the rows, a flaky case can come from the judge rather than your application. To measure the judge alone, repeat the evaluation on fixed outputs, without a `predict_fn`. See [Comparing Evaluation Runs](/genai/eval-monitor/comparing-evaluation-runs) to test whether one run is better than another.
