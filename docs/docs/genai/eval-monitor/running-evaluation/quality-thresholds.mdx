# Quality Thresholds

A quality threshold is the bar a scorer's run-level metric must clear for an evaluation run to count as passing. Pass thresholds to <APILink fn="mlflow.genai.evaluate">`mlflow.genai.evaluate`</APILink> in `quality_thresholds`, and it records them on the evaluation run alongside the metrics they apply to.

Thresholds belong to a run, not an experiment. When you change a scorer, for example by moving from v1 to v2 of a judge, each run keeps the bar it was evaluated against.

:::info[Experimental Feature]
Quality thresholds, including the `quality_thresholds` parameter of `mlflow.genai.evaluate`, were added as experimental in MLflow 3.17.2. The API and behavior may change or be removed in future releases.
:::

## Set a threshold

`quality_thresholds` is a dict that maps a scorer name to a <APILink fn="mlflow.genai.scorers.QualityThreshold">`QualityThreshold`</APILink>. Exactly one of `at_least` or `at_most` is required. By default, the bar applies to the mean of the scorer's per-row values:

```python
import mlflow
from mlflow.genai.scorers import Correctness, QualityThreshold, Safety

results = mlflow.genai.evaluate(
    data=eval_data,
    predict_fn=agent,
    scorers=[Correctness(), Safety()],
    quality_thresholds={
        "correctness": QualityThreshold(at_least=0.9),  # correctness/mean >= 0.9
        # Safety has no threshold
    },
)
```

For yes/no scorers, the mean is the pass rate, so `QualityThreshold(at_least=0.9)` on `correctness` means "at least 90% of rows are correct".

## Upper bounds and other aggregations

Use `at_most` for an upper bound, and `aggregation` to apply the bar to a different aggregation of the per-row values. `aggregation` is one of `"min"`, `"max"`, `"mean"` (the default), `"median"`, `"variance"`, or `"p90"`.

```python
from mlflow.genai.scorers import QualityThreshold, scorer


@scorer
def latency_s(trace) -> float:
    return trace.info.execution_duration / 1000


results = mlflow.genai.evaluate(
    data=eval_data,
    predict_fn=agent,
    scorers=[latency_s],
    quality_thresholds={
        "latency_s": QualityThreshold(at_most=2.0, aggregation="p90"),
    },
)
```

MLflow always computes the aggregation a threshold uses, even if it isn't in the scorer's `aggregations`.

## Match thresholds to scorers

Each key in `quality_thresholds` is a scorer's `name`, the name its metrics are logged under. Thresholds work with every scorer: built-in scorers, custom `@scorer` functions, judges from <APILink fn="mlflow.genai.judges.make_judge">`make_judge`</APILink>, ensembles from <APILink fn="mlflow.genai.scorers.make_scorer_ensemble">`make_scorer_ensemble`</APILink>, registered scorers, and third-party scorers (DeepEval, RAGAS, TruLens, Phoenix, Google ADK).

`evaluate` checks the keys before the run starts and raises if a key:

- **matches no scorer** passed to `evaluate`, for example because of a typo. The error lists the scorer names.
- **matches more than one scorer**. Give each scorer a unique `name`, for example `Guidelines(name="politeness", guidelines=...)`.

Notes:

- **Ensembles**: use the ensemble's name. A sub-scorer has no metric of its own on the run, so its name isn't a valid key.
- **Registered scorers**: thresholds aren't saved with a scorer. Use the registered name as the key:

  ```python
  from mlflow.genai.scorers import QualityThreshold, get_scorer

  results = mlflow.genai.evaluate(
      data=eval_data,
      predict_fn=agent,
      scorers=[get_scorer(name="my_scorer")],
      quality_thresholds={"my_scorer": QualityThreshold(at_least=0.85)},
  )
  ```

- **Third-party scorers**: the quality threshold is separate from the library's own per-row `threshold` argument, which decides whether a single row passes.

## Read thresholds from a run

`mlflow.genai.evaluate` stores the thresholds as JSON in the `mlflow.genaiEvaluate.qualityThresholds` run tag. Each rule names the metric it applies to:

```python
import json

run = mlflow.get_run(results.run_id)
thresholds = json.loads(run.data.tags["mlflow.genaiEvaluate.qualityThresholds"])

for rule in thresholds["rules"]:
    value = results.metrics.get(rule["metricKey"])
    print(rule["metricKey"], rule["comparator"], rule["threshold"], value)
# correctness/mean GTE 0.9 0.93
```

`comparator` is `GTE` for `at_least` and `LTE` for `at_most`. No tag is written when `quality_thresholds` is empty or not set.

## Limitations

- **One thresholded evaluation per run**: when `evaluate` runs inside an active run (`with mlflow.start_run():`), it writes into that run, and only the last evaluation's thresholds are kept. MLflow can't delete metrics, so if a scorer produces no metric in the last evaluation, its threshold is compared against the metric an earlier evaluation logged. Use a fresh run for each evaluation that has thresholds.
- **Numeric values only**: the threshold applies to an aggregated metric, so the scorer must return booleans, numbers, or yes/no values. Scorers that return other values (for example, categorical labels) or emit `Feedback` under a different name produce no matching metric. MLflow logs a warning and the threshold can't be checked.
- **Failed rows are left out**: the aggregation skips rows where the scorer raised an error, so a threshold can pass even if most rows weren't scored. MLflow logs a warning with the number of failed rows; check it before you rely on the result.
- **`EvaluationResult.passed` ignores thresholds**: `passed` requires every scorer's value to pass on every row. A run can therefore fail `passed` while still meeting its thresholds — for example, 95 of 100 rows correct against `at_least=0.9` fails `passed` (5 rows scored no) but meets the threshold. To check the thresholds in Python, read the run tag and compare each rule's `metricKey` against `results.metrics`, as shown above.
- **Size**: the serialized thresholds must fit in a run tag (8,000 characters), which is enough for well over a dozen scorers.
