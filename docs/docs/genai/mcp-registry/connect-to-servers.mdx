# Connect to MCP Servers

Access endpoints define how users and agents connect to MCP servers registered in the registry. While `server_json` includes `remotes` entries, organizations often deploy MCP servers internally at different URLs, rotate deployment endpoints, or route traffic through an MCP gateway or proxy. Access endpoints let you manage these real connection details independently of the immutable `server_json` configuration.

This guide covers creating endpoints, generating connection instructions, and refreshing tool definitions.

## Access Endpoints

An **MCPAccessEndpoint** is a connection record that pairs a URL and transport type with a specific server version or alias. Endpoints let you maintain stable connection configurations that track version promotions through aliases.

### Create an Access Endpoint

<Tabs>
  <TabItem value="ui" label="UI" default>
    <div class="flex-column">
      ![Create Access Endpoint](/images/llms/mcp-registry/create-access-endpoint.png)

      1. Open the MCP server detail page.
      2. In the **Access Endpoints** section, click **Create endpoint**.
      3. Enter the endpoint URL and select the transport type (`streamable-http` or `sse`).
      4. Pin the endpoint to a specific version or alias.
      5. Click **Create** to save.
    </div>

  </TabItem>
  <TabItem value="python" label="Python">
    <div class="flex-column">
      Use <APILink fn="mlflow.genai.create_mcp_access_endpoint" />:

      ```python
      import mlflow

      endpoint = mlflow.genai.create_mcp_access_endpoint(
          server_name="io.github.anthropic/brave-search",
          url="https://mcp.example.com/brave-search",
          transport_type="streamable-http",
          server_version="1.0.0",
      )

      # Or pin to an alias (endpoint follows alias as it moves between versions)
      endpoint = mlflow.genai.create_mcp_access_endpoint(
          server_name="io.github.anthropic/brave-search",
          url="https://mcp.example.com/brave-search",
          transport_type="streamable-http",
          server_alias="production",
      )
      ```

### Transport Types

| Type              | Description                                                                     |
| ----------------- | ------------------------------------------------------------------------------- |
| `streamable-http` | Streamable HTTP transport (recommended). The default when no type is specified. |
| `sse`             | Server-Sent Events transport.                                                   |

### Search and Manage Endpoints

```python
import mlflow

# List all endpoints for a server
endpoints = mlflow.genai.search_mcp_access_endpoints(
    server_name="io.github.anthropic/brave-search",
)

for ep in endpoints:
    resolved = ep.resolved_version.version if ep.resolved_version else None
    print(f"  {ep.url} ({ep.transport_type}) → version {resolved}")

endpoint = endpoints[0]

# Update an endpoint
mlflow.genai.update_mcp_access_endpoint(
    server_name="io.github.anthropic/brave-search",
    endpoint_id=endpoint.id,
    url="https://mcp-v2.example.com/brave-search",
)

# Delete an endpoint
mlflow.genai.delete_mcp_access_endpoint(
    server_name="io.github.anthropic/brave-search",
    endpoint_id=endpoint.id,
)
```

## Link Traces to MCP Servers

Call `span.link_mcp_server()` to record which registered MCP server an operation uses. Pass an
`MCPServerRef`, an `MCPServerVersion`, or an `MCPAccessEndpoint`:

```python
import mlflow
from mlflow.entities import MCPServerRef

with mlflow.start_span("weather.forecast", span_type="TOOL") as span:
    span.link_mcp_server(MCPServerRef("com.example/weather", version="1.0.0"), tool="forecast")
    # Invoke the MCP tool here.

# Resolve an alias to a concrete version when the span is annotated.
with mlflow.start_span("weather.discover") as span:
    span.link_mcp_server(MCPServerRef("com.example/weather", alias="production"))

# A name-only reference leaves the version unknown; it does not resolve "latest".
with mlflow.start_span("weather.resources") as span:
    span.link_mcp_server(MCPServerRef("com.example/weather"))
```

`version` and `alias` are mutually exclusive. Version strings are preserved exactly, including
surrounding whitespace.
For a version object returned by
`mlflow.genai.get_mcp_server_version()`, pass the object directly; no lookup is needed:

```python
version = mlflow.genai.get_mcp_server_version("com.example/weather", "1.0.0")
with mlflow.start_span("weather.forecast", span_type="TOOL") as span:
    span.link_mcp_server(version, tool="forecast")
```

You can also pass an access endpoint obtained from the registry:

```python
endpoint = mlflow.genai.get_mcp_access_endpoint(
    server_name="com.example/weather", endpoint_id="ae-weather"
)
with mlflow.start_span("weather.forecast", span_type="TOOL") as span:
    span.link_mcp_server(endpoint, tool="forecast")
```

Pass an `MCPServerRef`, `MCPServerVersion`, or `MCPAccessEndpoint`; raw URLs are not accepted.
If an endpoint resolves without a version, linking records only the server name. If its URL or
transport changes, reload the endpoint before linking.

Supply `tool` when tracing a tool invocation; omit it for discovery, resource, and prompt
operations. A span can link to only one server name/version pair. Attempts to change that
identity—including adding a version to a name-only link—raise an error.

Linking records the registry's intended server identity; it does not verify which version the
remote server serves.

Resolution uses the tracking server and workspace captured when the trace started. Version
and endpoint objects from another workspace are rejected. Alias lookup failures also raise an error, and failed
calls leave the span attributes unchanged. Stored traces retain the concrete version observed
when linked, even if an alias is later retargeted.

Manually linking a span does not require an MCP client framework or the `mcp` extra.

### Link spans exported through OTLP

When exporting OpenTelemetry spans directly to MLflow through OTLP, set the MCP attributes
on the span as literal strings, without JSON encoding:

```python
from opentelemetry import trace

tracer = trace.get_tracer(__name__)
with tracer.start_as_current_span("weather.forecast") as span:
    span.set_attribute("mlflow.mcp.server.name", "com.example/weather")
    span.set_attribute("mlflow.mcp.server.version", "1.0.0")
    span.set_attribute("mlflow.mcp.tool.name", "forecast")
```

The server name is required to create a link. Omit the version when it is unknown, and omit
the tool name for discovery, resource, and prompt operations. OTLP ingestion does not resolve
aliases. The workspace comes from the `X-MLFLOW-WORKSPACE` request header or the server's
configured default workspace.

## Connection Instructions

The MLflow UI generates ready-to-use connection instructions for registered MCP servers. Click the **Connect** button on any server card to see instructions for:

- **Claude Code**: A `claude mcp add` CLI command that configures the server in Claude Code
- **.mcp.json**: A JSON configuration snippet for adding the server to your `.mcp.json` file

<div style={{ width: "70%", margin: "20px" }}>

</div>

Connection instructions are generated from the server's packages (for local installation via npm, pip, Docker, etc.) and remotes (for connecting to deployed instances).

## Tool Discovery

MLflow can automatically discover the tools that an MCP server exposes by connecting to its remote endpoint.

### Automatic Discovery During Registration

When you register a server version without explicitly providing tools, MLflow connects to the first usable remote in `server_json.remotes[]` and queries the server's tool list. See [Register MCP Servers](/genai/mcp-registry/register-mcp-servers#tool-auto-discovery) for details.

### Refresh Tools

If a server's tools change after registration, you can re-discover them using the Python SDK. The UI also provides an **Auto-discover tools** button on the version detail page that displays the equivalent Python snippet to run.

When refreshing tools, MLflow uses an access endpoint that resolves to the requested version, whether it targets the version directly or through an alias. MLflow connects using that endpoint's URL and transport. If access endpoints are configured but none resolves to the requested version, the refresh fails without contacting `server_json.remotes`.

If no access endpoints are configured, MLflow uses the first remote with a non-empty URL and supported transport. It does not try later remotes if discovery fails. Headers passed to the refresh method are used for discovery in either case.

Use <APILink fn="mlflow.genai.refresh_mcp_server_version_tools" />:

```python
import mlflow

# Refresh tools from the live server
updated_version = mlflow.genai.refresh_mcp_server_version_tools(
    name="io.github.anthropic/brave-search",
    version="1.0.0",
)

for tool in updated_version.tools or []:
    print(f"  Tool: {tool.name} — {tool.description}")

# Preview discovered tools without saving (dry run)
preview = mlflow.genai.refresh_mcp_server_version_tools(
    name="io.github.anthropic/brave-search",
    version="1.0.0",
    dry_run=True,
)

# Provide auth headers for protected servers
updated_version = mlflow.genai.refresh_mcp_server_version_tools(
    name="io.github.anthropic/brave-search",
    version="1.0.0",
    mcp_server_access_headers={"Authorization": "Bearer <token>"},
)
```

:::note

Tool discovery requires the `mcp` extra: `pip install 'mlflow[mcp]'`. Discovered tools are a point-in-time snapshot. They will not be automatically kept in sync with the live server.

:::
